# Stage 9.7 Backup-code dashboard banner — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the dashboard banner that nudges a user to re-enrol their authenticator (or regenerate backup codes) when their last login used a backup code or when they have ≤7 codes remaining. Drive it from a real per-session server signal so the behaviour is multi-device-correct.

**Architecture:** Add one nullable boolean column (`UsedBackupCodeAtLogin`) to `UserSession`. Set it true on the backup-code branch of `AuthController.LoginTotp`, false on the TOTP branch. In `AuthController.Me`, read the value from the current session row keyed by the `sid` claim. On the SPA side, add a `BackupCodeLoginBanner` component that reads `useAuth()`, renders the existing `border-warning/30 bg-warning/10` recipe with a CTA that shifts copy based on `usedBackupCodeAtLastLogin`, and dismisses via React-local state (per-pageview only).

**Tech Stack:** .NET 10 / EF Core / PostgreSQL (Npgsql) / xUnit + FluentAssertions / React 19 + TypeScript / Vitest + RTL / react-i18next / Tailwind v4 / shadcn (base-nova).

**Spec:** `docs/superpowers/specs/2026-05-21-stage-9-7-backup-code-banner-design.md`

Create `ProjectCeres.Client/src/app/features/security/BackupCodeLoginBanner.tsx`:

```tsx
import { useState } from 'react';
import { useTranslation } from 'react-i18next';
import { Link } from 'react-router-dom';
import { AlertTriangle, X } from 'lucide-react';
import { Button } from '@/components/ui/button';
import { useAuth } from '../../auth/auth-context';

const BACKUP_CODE_BANNER_THRESHOLD = 7;

export function BackupCodeLoginBanner() {
  const { user } = useAuth();
  const { t } = useTranslation();
  const [dismissed, setDismissed] = useState(false);

  if (dismissed) return null;
  if (!user) return null;
  if (!user.twoFactorEnabled) return null;
  if (user.backupCodesRemaining > BACKUP_CODE_BANNER_THRESHOLD) return null;

  const variant: 'reenrol' | 'regenerate' = user.usedBackupCodeAtLastLogin
    ? 'reenrol'
    : 'regenerate';
  const ns = `dashboard.backupCodeBanner.${variant}` as const;

  return (
    <div
      role="status"
      aria-live="polite"
      className="flex items-start gap-3 rounded-md border border-warning/30 bg-warning/10 p-4 text-sm"
    >
      <AlertTriangle className="mt-0.5 h-5 w-5 shrink-0 text-warning" aria-hidden />
      <div className="flex-1 space-y-2">
        <p>{t(`${ns}.body`, { count: user.backupCodesRemaining })}</p>
        <Button asChild variant="link" size="sm" className="h-auto p-0">
          <Link to="/security">{t(`${ns}.cta`)}</Link>
        </Button>
      </div>
      <Button
        type="button"
        variant="ghost"
        size="icon"
        className="-mr-2 -mt-1 h-7 w-7 shrink-0"
        onClick={() => setDismissed(true)}
        aria-label={t('dashboard.backupCodeBanner.dismiss')}
      >
        <X className="h-4 w-4" />
      </Button>
    </div>
  );
}
```

Notes on the choices:
- Constant `BACKUP_CODE_BANNER_THRESHOLD = 7` named explicitly so the magic number doesn't recur. If a future change moves the threshold, one edit suffices.
- The interpolation `{ count: user.backupCodesRemaining }` triggers i18next's plural lookup (`body_one` vs `body_other`).
- `role="status"` paired with `aria-live="polite"` matches the "non-interrupting nudge" semantic.
- `AlertTriangle` is `aria-hidden` because the message text already conveys the warning.
- Two real `<Button>` elements: one wrapping the `<Link>` (real anchor under the hood thanks to `asChild`), one for dismiss. Both keyboard-navigable.
- The `border-warning/30 bg-warning/10 text-warning` recipe matches the existing precedents at `TotpEnrollStep2BackupCodes.tsx:75-77` and `BudgetCreate.tsx:118`.
