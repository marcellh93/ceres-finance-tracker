# Stage 12.13 — CI Pipeline (GitHub Actions) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A GitHub Actions workflow that runs the full build + test + quality gate on a fresh, stateless environment on every push to `main` — the un-tiered, environment-independent superset of the local Stop-hook test gate.

**Architecture:** One workflow file (`.github/workflows/ci.yml`) with five parallel `ubuntu-latest` jobs (fail-fast off), each provisioning its own Postgres 16 service where needed. A new shared shell script (`tools/ci/setup-test-db.sh`) becomes the single source of DB provisioning, consumed by both CI and the existing `tools/e2e/run-server.sh` so the two never drift.

**Tech Stack:** GitHub Actions · .NET 10 (`dotnet`, `dotnet-ef`) · pnpm 10.33.2 · Node 22 · Playwright · PostgreSQL 16 · gitleaks · Bash.

**Spec:** `docs/superpowers/specs/2026-09-10-stage-12-13-ci-design.md`

## Global Constraints

- **Stay on main** — no branches, no PRs, no worktrees. Commit straight to `main`.
- **CI triggers:** `push` to `main` (active) + `pull_request` (dormant) + `workflow_dispatch` (manual). No branch-protection rules.
- **.NET 10** (`net10.0`); **pnpm pinned `10.33.2`** (from `packageManager` in `ProjectCeres.Client/package.json`); **Node 22 LTS** in CI.
- **No secrets in the workflow at all** — no GitHub Secrets, and no committed secret literal. The integration suite supplies its own token-lookup secret via `WafCollection.cs` `UseSetting` (the §12.12 fix), so `dotnet-test` needs only a reachable Postgres; the E2E job's `run-server.sh` generates a fresh one with `openssl rand -base64 32` at boot. DB access uses the `*_dev_password` role passwords already committed in `scripts/setup-postgres-roles.sql`. Resend not needed (Dev/Test → `LogOnlyEmailService`). (A committed base64 token literal was removed after gitleaks — our own secret-scanner — flagged it; generating/self-supplying is both cleaner and scanner-clean.)
- **No drift** — each CI job runs the same command the Stop hook (`.claude/hooks/run-tests.sh`) / build-matrix (`tools/agent-env/build-matrix.sh`) already runs. CI is their superset, not a second definition of "passing."
- **The roadmap-consistency PostToolUse hook (`.claude/hooks/roadmap-consistency-check.js`) must stay green** on every roadmap edit.
- **Debug build** (matches the Stop hook), not Release.
- **No Co-Authored-By trailer** in any commit.
- **Two databases:** integration tests use `project_ceres_test`; E2E uses `project_ceres_e2e`. They are separate.
- **Honest limit:** a real Actions run only happens on the user's push. The plan's final task is a *tracked, unfaked* verification `[ ]` the user satisfies by pushing — never assert CI is green from local work.

**Files:**
- Create: `tools/ci/setup-test-db.sh`
- Modify: `tools/e2e/run-server.sh:19-32` (replace steps 1–3 with a call to the new script)

**Interfaces:**
- Produces: `tools/ci/setup-test-db.sh <db-name>` — creates `<db-name>` if absent, applies `scripts/setup-postgres-roles.sql` to it, then runs `dotnet ef database update` as `ceres_migrator` against it. Assumes `psql`, `createdb`, and `dotnet-ef` are on PATH and Postgres is reachable at `localhost:5432`. Reads no env; the migrator password is the committed `ceres_migrator_dev_password`. Exits non-zero on any failure (`set -euo pipefail`).

- [ ] **Step 1: Write the script**

Create `tools/ci/setup-test-db.sh`:

```bash
#!/usr/bin/env bash
# setup-test-db.sh — single source of Ceres database provisioning.
# Creates the named DB (if absent), applies the role/grant SQL, and migrates it
# as ceres_migrator. Consumed by both CI (.github/workflows/ci.yml) and the E2E
# webServer bootstrap (tools/e2e/run-server.sh), so the two never drift.
#
# Usage:  tools/ci/setup-test-db.sh <db-name>
# Assumes: psql, createdb, dotnet-ef on PATH; Postgres reachable at localhost:5432.
set -euo pipefail

DB="${1:?usage: setup-test-db.sh <db-name>}"
SCRIPT_DIR="$(cd "$(dirname "${BASH_SOURCE[0]}")" && pwd)"
REPO_ROOT="$(cd "$SCRIPT_DIR/../.." && pwd)"
MIGRATE_CONN="Host=localhost;Database=${DB};Username=ceres_migrator;Password=ceres_migrator_dev_password"

log() { echo "[setup-test-db] $*" >&2; }

# 1. Create DB if missing.
if ! psql -lqt | cut -d '|' -f1 | grep -qw "$DB"; then
  log "creating database $DB"
  createdb "$DB"
fi

# 2. Provision roles/grants for THIS database (grants are per-database).
log "applying setup-postgres-roles.sql to $DB"
psql -d "$DB" -v ON_ERROR_STOP=1 -f "$REPO_ROOT/scripts/setup-postgres-roles.sql" >/dev/null

# 3. Migrate as ceres_migrator (the --connection flag is mandatory — no design-time factory).
log "migrating $DB"
dotnet ef database update --project "$REPO_ROOT/ProjectCeres" \
  --context AppDbContext --connection "$MIGRATE_CONN" >/dev/null

log "done: $DB provisioned + migrated"
```

### Task 2: Write the CI workflow — dotnet-test, analyzer-test, client-test jobs

The three DB-and-build jobs. (E2E and repo-hygiene are Task 3, split only because E2E's matrix + caching is the most iteration-prone part and deserves its own commit boundary.)

**Files:**
- Create: `.github/workflows/ci.yml`

**Interfaces:**
- Consumes: `tools/ci/setup-test-db.sh` from Task 1.
- Produces: a workflow with `on:` triggers, `concurrency:`, and three jobs (`dotnet-test`, `analyzer-test`, `client-test`). Task 3 appends two more jobs to the same file.

- [ ] **Step 1: Write the workflow head + the three jobs**

Create `.github/workflows/ci.yml`:

```yaml
name: CI

on:
  push:
    branches: [main]
  pull_request:            # dormant — no PR workflow today; armed for the future
  workflow_dispatch:       # manual "Run workflow" button

# Supersede in-flight runs on rapid pushes to the same ref (saves minutes;
# does not hide failures within a run).
concurrency:
  group: ci-${{ github.ref }}
  cancel-in-progress: true

jobs:
  dotnet-test:
    runs-on: ubuntu-latest
    services:
      postgres:
        image: postgres:16
        env:
          POSTGRES_PASSWORD: postgres
        ports: ["5432:5432"]
        options: >-
          --health-cmd pg_isready
          --health-interval 10s
          --health-timeout 5s
          --health-retries 5
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-dotnet@v4
        with:
          dotnet-version: "10.0.x"
      - name: Restore dotnet tools (dotnet-ef)
        run: dotnet tool restore || dotnet tool install --global dotnet-ef
      - name: Ensure dotnet-ef on PATH
        run: echo "$HOME/.dotnet/tools" >> "$GITHUB_PATH"
      - name: Provision + migrate project_ceres_test
        run: tools/ci/setup-test-db.sh project_ceres_test
        env:
          PGHOST: localhost
          PGUSER: postgres
          PGPASSWORD: postgres
      - name: Build
        run: dotnet build ProjectCeres.Tests/ProjectCeres.Tests.csproj
      - name: Full test suite
        # No secret env var needed: WafCollection.cs supplies Authentication:TokenLookupSecret:Secret
        # itself via UseSetting (the Stage 12.12 fix), so the integration suite is self-sufficient
        # on secrets — it needs only a reachable Postgres. E2E generates its own in run-server.sh.
        run: dotnet test ProjectCeres.Tests/ProjectCeres.Tests.csproj --no-build

  analyzer-test:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-dotnet@v4
        with:
          dotnet-version: "10.0.x"
      - name: Restore (populates the CodeAnalysis.Testing ref-pack cache)
        run: dotnet restore ProjectCeres.Analyzers.Tests/ProjectCeres.Analyzers.Tests.csproj
      - name: Analyzer tests
        run: dotnet test ProjectCeres.Analyzers.Tests/ProjectCeres.Analyzers.Tests.csproj

  client-test:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: pnpm/action-setup@v4          # reads version from packageManager
      - uses: actions/setup-node@v4
        with:
          node-version: "22"
          cache: pnpm
          cache-dependency-path: ProjectCeres.Client/pnpm-lock.yaml
      - name: Install
        run: pnpm --dir ProjectCeres.Client install --frozen-lockfile
      - name: Build (tsc + vite + check-size)
        run: pnpm --dir ProjectCeres.Client build
      - name: Vitest
        run: pnpm --dir ProjectCeres.Client test
```

```yaml
  e2e:
    runs-on: ubuntu-latest
    strategy:
      fail-fast: false
      matrix:
        project: [chromium, firefox, webkit]
    services:
      postgres:
        image: postgres:16
        env:
          POSTGRES_PASSWORD: postgres
        ports: ["5432:5432"]
        options: >-
          --health-cmd pg_isready
          --health-interval 10s
          --health-timeout 5s
          --health-retries 5
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-dotnet@v4
        with:
          dotnet-version: "10.0.x"
      - name: Restore dotnet tools (dotnet-ef)
        run: dotnet tool restore || dotnet tool install --global dotnet-ef
      - run: echo "$HOME/.dotnet/tools" >> "$GITHUB_PATH"
      - uses: pnpm/action-setup@v4
      - uses: actions/setup-node@v4
        with:
          node-version: "22"
          cache: pnpm
          cache-dependency-path: ProjectCeres.Client/pnpm-lock.yaml
      - name: Install client deps
        run: pnpm --dir ProjectCeres.Client install --frozen-lockfile
      - name: Resolve Playwright version (for the cache key)
        id: pw
        run: echo "version=$(pnpm --dir ProjectCeres.Client ls @playwright/test --depth 0 --parseable 2>/dev/null | sed 's/.*@//' || echo unknown)" >> "$GITHUB_OUTPUT"
      - name: Cache Playwright browsers
        uses: actions/cache@v4
        with:
          path: ~/.cache/ms-playwright
          key: playwright-${{ runner.os }}-${{ steps.pw.outputs.version }}
      - name: Install Playwright browsers
        run: pnpm --dir ProjectCeres.Client exec playwright install --with-deps ${{ matrix.project }}
      - name: E2E (${{ matrix.project }})
        run: pnpm --dir ProjectCeres.Client exec playwright test --config e2e/playwright.golden.config.ts --project=${{ matrix.project }}
        env:
          PGHOST: localhost
          PGUSER: postgres
          PGPASSWORD: postgres
      - name: Upload traces + report on failure
        if: failure()
        uses: actions/upload-artifact@v4
        with:
          name: e2e-artifacts-${{ matrix.project }}
          path: ProjectCeres.Client/e2e/.artifacts/
          retention-days: 7

  repo-hygiene:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
        with:
          fetch-depth: 0          # gitleaks scans history
      - uses: actions/setup-dotnet@v4
        with:
          dotnet-version: "10.0.x"
      - name: Vulnerable-package scan (fail on any finding)
        run: |
          dotnet restore ProjectCeres.sln 2>/dev/null || dotnet restore
          OUT="$(dotnet list package --vulnerable --include-transitive 2>&1 || true)"
          echo "$OUT"
          if echo "$OUT" | grep -qiE '>\s*[0-9].*(Critical|High|Moderate|Low)'; then
            echo "::error::Vulnerable package(s) reported"; exit 1
          fi
      - name: Secret scan (gitleaks)
        uses: gitleaks/gitleaks-action@v2
      - name: Node hook self-tests
        run: node --test .claude/hooks/__tests__/
      - name: Roadmap marker/status consistency
        run: |
          for f in docs/roadmap-phase-*.md; do
            node -e "const fs=require('fs');const {scan}=require('./.claude/hooks/roadmap-consistency-check.js');const g=scan(fs.readFileSync(process.argv[1],'utf8'));if(g.length){console.error(process.argv[1]+':');g.forEach(x=>console.error('  '+x));process.exit(1)}" "$f"
          done
          echo "roadmaps consistent"
```

```markdown
## Continuous Integration (Stage 12.13)

CI runs on GitHub Actions (`.github/workflows/ci.yml`) on every push to `main`
(plus a manual `workflow_dispatch` button; the `pull_request` trigger is dormant
because the project commits straight to `main`).

**CI is additive to the local Stop-hook gate, not a replacement.** The Stop hook
(`.claude/hooks/run-tests.sh`) is the fast, *tiered* inner-loop gate — it skips
(tier 0), runs unit-only (tier 1), or the full suite (tier 2) based on what a turn
changed, on the author's machine. CI is the *un-tiered, fresh-environment superset*:
it always runs everything, against a clean checkout with zero local state, and it
runs the things the Stop hook never does (E2E across three browsers, dependency +
secret scanning). The two cover each other's blind spots — the Stop hook keeps the
inner loop fast; CI proves it works somewhere other than the author's Mac (exactly
the class of bug Stage 12.12 was: a suite silently depending on a personal secrets file).

**No drift:** each CI job runs the same command the Stop hook / evidence build-matrix
already run. DB provisioning is shared via `tools/ci/setup-test-db.sh` (also used by
`tools/e2e/run-server.sh`), so "CI passes" ≡ "the suite passes on a clean machine."

**Jobs** (five, parallel, fail-fast off — one push surfaces all failures):
| Job | Runs |
|---|---|
| `dotnet-test` | full `dotnet test` (no filter) against a Postgres 16 service |
| `analyzer-test` | the Roslyn analyzer suite |
| `client-test` | `pnpm build` (tsc + vite + size budget) + Vitest |
| `e2e` | Playwright sharded over chromium/firefox/webkit; traces on failure |
| `repo-hygiene` | `dotnet list package --vulnerable` + gitleaks + Node hook tests + roadmap consistency |

**Secrets:** none real — fixed test-only values (the `*_dev_password` role passwords
in `scripts/setup-postgres-roles.sql` and a fixed test token-lookup secret). Real
production secrets arrive at actual Stage 16 hosting.
```
